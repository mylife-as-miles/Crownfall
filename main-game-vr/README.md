# Crownfall Quest

The hands-first Meta Quest version of the approved Crownfall menu. It was created with `npm create @iwsdk@latest` and currently pins IWSDK `1.1.0-rc.2`. Node 24 is recommended; the package declares the SDK-supported Node ranges, starting at 20.19.

From the repository root:

```sh
npm run setup
npm run dev:quest
npm run build
npm run test:quest
npm run check:sync
```

`dev:quest` uses the IWSDK-managed server and browser. Its HTTPS endpoint is normally `https://localhost:8081/`; the CLI also reports network addresses for a headset on the same network. Use an HTTPS host for a production WebXR experience. No production deployment is performed by these scripts.

The setup helper skips the optional CUDA download used by IWSDK's development-reference helper; both app runtimes and CPU reference tooling remain available. Direct installation on Linux can use `ONNXRUNTIME_NODE_INSTALL_CUDA=skip npm ci`.

## The hand-only visit

Open the page in a Quest browser, enable hand tracking and select Enter VR with the browser's hand pointer. No controller pairing is required. The immersive session requests hand tracking as a required feature; unsupported or denied entry leaves the browser preview and a retryable explanation.

The first visit explains pointing and pinching, and direct fingertip presses on nearby controls. Start a short three-arena visit or skip to the menu. Next and Previous are hand buttons; Finish creates a visibly distinct completion state. Home also offers Short visit so the moment can be replayed. Back returns to the menu, and Exit VR returns to the browser. There are no timed gates or artificial waiting periods, and the visit can finish well within ten minutes. This is an artwork/menu experience: chess, campaign progression, online duels and replay playback are not connected.

All Home, Play, Showcase, chapter, settings and modal controls are native spatial UIKitML buttons. Their design follows the desktop1280×720 canvas: full artwork with the same focal crops, overlaid Barlow headings, original card/grid proportions, unboxed navigation, patterned settings tiles and borderless dialogs. The whole canvas scales uniformly in world space so compact35-unit rows remain hand-sized; controls do not become a different dashboard. Both `RayInteractable` and `PokeInteractable` are authored on the panel. Back, Pause, Recenter and Exit VR remain discoverable without a keyboard or controller. Covered actions are blocked while outgoing views briefly fade.

The menu stays in world space, rather than following every head movement. Recenter places the room in front of the current view without moving or tilting the viewer. Either hand works; the other hand may remain out of view. Losing both tracked hands or backgrounding the immersive session pauses and retains the current menu, dialog and visit step. Bring a hand back and select Resume. Explicit Exit and re-entry retain the in-memory place; completed onboarding and comfort preferences persist on this browser.

## Quest settings

The six categories retain Crownfall's labels but use headset-appropriate controls. General contains ambient motion, hand hints and contrast. Controls explains pointing/pinching, touch, Back, Pause, Recenter and Exit; Input reports actual current wrist tracking. Video offers render quality, larger menu/text sizes, menu distance, menu height and seated/standing placement; distance and height also place My Legacy's reading panel. Headset resolution and frame timing stay managed by the immersive session; desktop frame caps and fullscreen controls are not applied to VR. Render quality adjusts preview resolution and headset foveation where supported. Audio volume is a saved preference with its currently absent playback disclosed. Credits identifies the supplied assets and SDK.

The real sorcerer loads lazily through IWSDK's `AssetManager`, after the menu is usable. Its named Idle loops at authored speed. The warm background wash, teal/gold shader motes, aura and light palette follow desktop. Quality changes particle density; pausing/reduced motion freeze their clock and the rig. Model failure leaves the menu operational and exposes Retry creature. The existing local Draco decoders are remapped through the public loading manager.

## My Legacy

Home → My Legacy opens the immersive Legacy destination as its own place (the `legacy` route), not an information dialog. While it is shown the menu panel, the sorcerer and the menu atmosphere are hidden and stop updating; Return to Home restores them. Chess matches are not connected to My Legacy in this build: accepting a challenge records the acceptance and shows "Awaiting the board", and no match result is ever invented.

**Lazy by design.** Nothing of My Legacy loads before Home is interactive. `src/crownfall-system.ts` only holds a type import; the first time the `legacy` route opens it `import()`s `src/legacy/legacy-experience.ts` (its own chunk, with the shared Legacy domain and content), and `QuestLegacyExperience.create` instantiates the two panel documents from their `priority: 'lazy'` manifest entries (`src/legacy/legacy-manifest.ts`, kept free of Legacy code so the asset manifest stays small) under the scene-authored `legacy-anchor`. While that happens Home stays in view with "Preparing My Legacy..." on its status line; a failure returns to Home with an honest status line, and choosing My Legacy again retries. The production startup chunk contains no Legacy code or copy, and `performance` marks (`crownfall:menu-ready`, `crownfall:legacy-requested`, `crownfall:legacy-ready`) make both costs measurable. `node_modules/.bin/tsx scripts/measure-launch.ts --variant lazy=dist [--variant none=<dist>]` measures Home launch-to-interactive for built variants with and without a stored banner, and lists any Legacy request made before entry.

**Staging.** The scene-authored `legacy-anchor` is placed at the viewer's eye, facing where the menu faces. Recenter repositions it, and the menu, in front of the current view; the viewer is never moved or rotated. The environment is created on first entry and parented under that anchor. `src/legacy/legacy-staging.ts` places the reading panel at the environment's published `panelAnchors.primary` (the stand-in puts its centre about 4 degrees below eye level at 1.4 m, like the Home menu), moved along its line of sight by Menu Distance and up or down by Menu Height. Larger Text Size grows the panel about its centre; it rises only as far as it must to keep its bottom edge above the holding's landmarks, so a ray to its lowest controls never crosses a landmark, and a panel too tall to fit under +24 degrees steps back instead. The touch tray sits about 0.6 m from the eye, centred below the line of sight and below the holding's front edge, within reach of either hand whether seated or standing. Posture, render quality (including foveation) and reduced motion follow the existing Quest preferences.

**Environment seam.** `src/legacy/environment-provider.ts` discovers the environment workflow's `src/legacy/environment/createLegacyEnvironment.ts` with a lazy `import.meta.glob`. Until that module exists, or if it fails, gameplay's stand-in in `src/legacy/standin/` is used. The stand-in is a small, neutral diorama with four labelled landmark markers in one shallow arc (so a hand ray from either side reaches each without crossing another's pick volume), a gold marker above the landmark whose inspector is open, and a visible "Environment stand-in" caption. It is not the authored Bannerhold.

**Panels.** `scripts/generate-quest-legacy-ui.ts` builds `public/ui/legacy.uikitml` (the reading panel) and `public/ui/legacy-dock.uikitml` (the touch tray) from shared Legacy content and copy. Do not hand-edit them; Vite regenerates them and `npm run check:sync` fails when they are stale. The generator enforces comfort gates at each document's viewing distance: every control subtends at least 3 degrees (tray controls are also at least 3.5 cm for a fingertip) and no readable copy is below 15 units or 0.9 degrees. Text is mapped to the ASCII glyphs of the spatial font, so `·` reads as `/` and dashes read as `-`. UIKitML gives an empty `<span>` no text node, so every live text starts with a placeholder (class `lg-live`) that the runtime clears, and the generator rejects empty text spans. Controls are plain containers whose hover, selection and disabled looks are set from code (`src/legacy/legacy-button-style.ts`), so the generator also rejects `<button>` and `:hover`. Shared copy is shown whole: nothing on either panel is shortened to fit. The panels cover:

- founding: the four nations; quick name suggestions with Other names, plus an optional large-key keyboard; heraldry presets and per-element cycling with a live preview rasterized by the shared heraldry code; the confirmation with an optional motto (typed on the same keyboard, in sentence case); and the raising beat ("A banner is raised"), which waits for Continue rather than moving a reader on;
- the aftermath: at most two prominent messages, each shown whole, with Back (set aside for this visit) and Acknowledge, and a way back to it from the overview;
- the overview with the house crest and a landmark list as a hand alternative to pointing at the holding;
- the four landmark inspectors, which show the same shared data as desktop: the Banner Hall's arms, motto, standing, honours and both houses with their arms (Dissolve banner lives here, with its confirmation, and is replaced by the shared lock note in development previews); the Muster Grounds' representative ledger (banner, appointment, file, condition, captor or promotion, musters, captures, times taken), a visible empty place for a captive, and the house's side of the formation from the shared Muster formation, with the nomination of a member and an open file on its own view; the War Record's Conflicts, Unresolved matters and Ledger sections; and the Herald's Station notices, where a challenge states its wager as four short terms from the shared builder, repeated on Accept ("Awaiting the board" follows);
- the touch tray: Back and the current view's primary action, mirrored for fingertip use (a destructive confirmation is never mirrored), Return to Home, Recenter, Pause and Exit VR, plus a session line that says "Saved on this device" only when the banner on show is stored here.

**Saves and sessions.** Banners persist in this browser's `localStorage` under `crownfall.legacy.save`, through the shared `shared/legacy` persistence and the same schema as desktop. There is no sync between devices. `src/legacy/legacy-session.ts` holds the rule that only a persistent production session with working storage writes, and its tests prove with a recording storage that guest, preview and missing-preview sessions make no storage call at all. `?legacy=fresh` starts a guest banner that never reads or writes storage. `?legacyPreview=<id>` loads a development preview built from fixture records (fetched only for such URLs). Both are labelled in the headset (the panel band and the tray) and on the browser entry panel. An unreadable save, or one from a newer version, is left untouched, and you can raise a new banner or continue as a guest.

**Hands and comfort.** Either hand points and pinches at the reading panel, the tray and the holding's landmarks (the stand-in's landmark proxies are `RayInteractable` and `PokeInteractable`). The tray also takes direct fingertip presses, but only while the head looks down towards it: IWSDK lets a fingertip within 15 cm of a pokeable surface take over that hand's ray, so a hand resting near an always-pokeable tray would swallow every pinch aimed at the reading panel. The tray therefore becomes `PokeInteractable` once the head pitches below a gate set 6 degrees under the panel's bottom edge (or midway to the tray when the two are closer) and stops again once the head rises 4 degrees above it (`trayTouchActive` in `src/legacy/legacy-staging.ts`, tested for every posture, Text Size, Menu Distance and Menu Height). The reading panel, 1.4 m away, is never pokeable. Losing both hands pauses My Legacy; Resume appears once a hand returns, and restores the same Legacy view. Exit VR keeps the Legacy place for re-entry.

**Verification in browser emulation.** With the managed runtime started with `--allow-browser-automation` (on a shared host, `CROWNFALL_QUEST_PORT` moves it off 8081), `node scripts/verify-legacy.mjs` drives the destination with hand rays, pinches and fingertip presses only, both controllers disconnected, and asserts the Legacy fields of `CrownfallQuestState` after each step: Home with no Legacy request made, the lazy first entry, the panel and tray angles and distances, founding with a typed motto and the raising beat, every landmark from the holding (right hand) and the list (left hand), the War Record's sections, a nomination, the challenge's terms, Accept → "Awaiting the board", tray presses (left and right fingertips), hand loss → pause → Resume, the tray's Pause and the pause view's Return to Home, Recenter, Exit VR and re-entry, the save written to this browser and its reload. `--session guest` and `--session preview:<id>` prove that those sessions leave a stored record byte-identical. `node scripts/capture-legacy.mjs` writes mono 60° captures with `--session production`, `guest`, `preview:<id>`, `recovery:corrupt`, `recovery:future`, `comfort:125`, `comfort:150` or `standing`. Both share `scripts/legacy-driver.mjs`, whose panel pinches start from a relaxed hand in front of the chest and whose tray pinches start from a hand raised well clear of the tray (a fingertip near it would poke instead).

Software-emulation accommodations, all recorded in the evidence: a 640×480 viewport (800×560 for captures), Render Quality Low and Ambient Motion Off, the short visit marked complete, `VITE_CROWNFALL_EMULATOR_SCALE=0.25`, and, for pinches on the Home menu only, the emulated head looking almost straight down. On a loaded shared host SwiftShader takes over a second per frame for the 80k-triangle sorcerer, longer than the pointer's 800 ms click window; looking down removes it from view and the same pinch lands. The emulated fingertip press moves the hand to the control, so reach is evidenced by the control's measured distance from the eye, not by a body model. None of this is a physical Quest test.

## Shared updates

`../shared/menu/` owns common content, feature availability, modal copy, palette and design geometry. `../scripts/generate-quest-ui.ts` creates the static `public/ui/menu.uikitml` panel. The Vite integration regenerates it and copies the canonical desktop assets during direct IWSDK CLI startup and production builds. Changes to shared data/assets restart the same managed runtime; generated asset copies are ignored by Git. `npm run check:sync` verifies deterministic UI generation, desktop token use and asset hashes.

Each app has a separate dependency tree. Do not hoist or substitute Three: the Quest app uses IWSDK's exact `super-three` alias, while desktop retains its existing Three runtime.

## Verification

```sh
npm run typecheck
npm run test
npm run build
npx @iwsdk/cli dev up --headless --timeout 45000
npx @iwsdk/cli runtime wait --timeout 45000
# Select the page's Enter VR control, then use native hand input.
```

The pure state suite checks routes, unsupported/locked previews, modal isolation, comfort values, pause/resume context and guarded completion. Immersive behavior must additionally be exercised through actual emulated hand inputs and named application state; flat preview screenshots do not prove it. The runtime component `CrownfallQuestState` exposes the selected view, dialog, tracking, visit progress, comfort values and animation time for inspection.

With the managed runtime already running, `node scripts/verify-runtime.mjs` exercises the full menu with hand rays and pinches, disconnects both controllers, and verifies actual Exit postconditions. The recorded run in `artifacts/hands/verification.json` preserves its original six passing UI groups and an SDK ended-session acknowledgement error after successful Exit. `exit-postcondition.json` and the five-group `session-verification.json` establish the actual Exit, hand-loss recovery, repeat visit and re-entry outcomes; `result.json` composes those records without rewriting the original failure. `verify-session.mjs` is a closeout of that recorded run, not an independent clean-start suite.

The Home menu's emulated input checks used mono rendering. Native fingertip touch is wired on the Home menu, but its emulator contact helper exceeded the click window on this software-rendered host, so direct poke on the Home menu is not claimed as a passed runtime test (My Legacy's tray presses are verified separately, above). A later stereo capture timed out and the managed browser closed; one managed recovery produced the final mono capture. See `artifacts/final/capture-evidence.json` and the bounded visual comparison in `artifacts/ui-runtime-review.jpg`. These are development captures, including emulator overlays, not a production headset recording.

Browser emulation is separate from a physical Quest smoke test. Physical tracking reliability, seated comfort, on-device cold start and the headset's 72–90 Hz rendering budget require on-headset measurement before challenge acceptance is claimed. The project is not merged, deployed or submitted to a challenge by this work.

For software-only headless emulation, an untracked `.env.local` may set `VITE_CROWNFALL_EMULATOR_SCALE=0.25` before starting the managed runtime. It requests a reduced development immersive framebuffer for software testing; actual emulation framebuffer size must be measured separately. Production ignores this flag. Remove it for physical-headset development, and disclose it with emulated evidence.

## Screenshot gallery

Current desktop-design verification and fresh renders are in `artifacts/parity/`, driven by `node scripts/verify-parity.mjs`. It starts through the explicit browser Enter VR button because automatic session offering is disabled, then uses actual hand inputs. Compact inspection sizes allow a .002-unit Float32 tolerance.

The earlier complete33-screen menu/state gallery in [artifacts/screens/README.md](artifacts/screens/README.md) records the previous visual adaptation at9817e3f. Its PDF/PNGs remain available as historical evidence; they do not show the restored desktop design.

To refresh it in the managed test browser, enable `--allow-browser-automation` when starting the headless runtime, run `npx @iwsdk/cli browser run scripts/prepare-gallery.mjs`, then `node scripts/capture-all-screens.mjs`. Preparation clears only the test browser's completed-onboarding flag; the real visit completes it again. Capture uses actual hand selections and named state assertions. `python scripts/build-screen-gallery.py` packages the files and requires Pillow. The gallery runner expects a fresh browser preview with no active immersive session.

A stopped capture can continue with `node scripts/capture-all-screens.mjs --resume` in the same session. Completed screenshots are retained, and prior selection errors remain in the manifest.
